# Klarwert SEO: Content & Technical Design

Date: 2026-08-01

## Purpose

Make Klarwert discoverable via search engines for English-speaking searchers
interested in Trade Republic portfolio analysis. Concretely: rank for long-tail
queries such as "Trade Republic CSV export", "Trade Republic tax report", and
"Trade Republic performance". The current GitHub Pages site is a single thin
landing page (`docs/index.html`); this design expands it into a multi-page,
keyword-targeted site with full technical SEO, generated by a small Python
static-site generator that fits the existing Python project.

## Decisions (from brainstorming)

- Goal: rank for search terms (not merely shareability).
- Audience: international / English content only.
- Scope: content + technical on-page SEO (no off-page promotion in this pass).
- Domain: stay on `https://d0k3n.github.io/klarwert`; design canonicals and
  sitemap so a custom domain can be dropped in later with a one-line change.
- Build: tiny Python static generator (stdlib only, no new dependencies).

## Hosting & build output

- GitHub Pages serves the `/docs` folder from branch `main`
  (one-time repo setting: Settings -> Pages -> Deploy from branch `main`,
  path `/docs`).
- `docs/` is build output generated by `build_docs.py`; source lives in
  `site/`.
- No JavaScript, no external resources, system font stack (fast, private,
  mobile-friendly — already true of the current page).

## Source layout

```
site/
  base.html            # shared <head> (all SEO tags), header, nav, footer
  index.md             # page content as Markdown with frontmatter
  tax-report.md
  csv-guide.md
  performance.md
  dividends.md
  faq.md
build_docs.py          # render script (stdlib only)
docs/                  # build output — what GitHub Pages serves
```

Each page is a Markdown file with frontmatter:

- `title` — used in `<title>` and `<h1>`
- `description` — used in `<meta name="description">` and `og:description`
- `slug` — canonical URL path
- `nav_title` — short label for the header nav
- `lastmod` — optional override; default derived from the most recent git
  commit that touched that page's Markdown source file (via `git log -1
  --format=%cs -- <file>`), so sitemap lastmod dates track content edits

`build_docs.py`:
- Renders each Markdown page into `base.html` -> `docs/<slug>.html`.
- Generates `docs/sitemap.xml` (all pages, correct lastmod) and
  `docs/robots.txt` (allow all, point to sitemap).
- Generates `docs/404.html` (styled not-found page).
- Renders the shared template only once per page so head tags stay consistent.

Markdown rendering uses a tiny hand-rolled renderer (headings, paragraphs,
code blocks, ordered/unordered lists, inline code, links, tables, bold/italic).
If that proves fiddly during implementation, fall back to adding the
pure-Python `markdown` package to `requirements.txt` — no other dependencies.

## Pages & keyword map

Canonical base URL (single constant in the generator, easy to swap later):
`https://d0k3n.github.io/klarwert`.

| Page | URL slug | Target keywords |
| --- | --- | --- |
| Home (expanded landing) | `/` | Trade Republic portfolio analyzer / tracker |
| Tax report guide | `/trade-republic-tax-report` | Trade Republic tax report, capital gains tax calculation |
| CSV guide | `/trade-republic-csv` | Trade Republic CSV export, analyze Trade Republic transactions |
| Performance guide | `/trade-republic-performance` | Trade Republic performance, annualized return, unrealized P&L |
| Dividends guide | `/trade-republic-dividends` | Trade Republic dividend tracker, dividend yield |
| FAQ | `/faq` | "Does Trade Republic have an API?", "How to export transactions from Trade Republic" (question queries) |

Guidance for content:

- Each guide page is a genuinely useful tutorial: what the Trade Republic CSV
  export contains, how taxes / FIFO / XIRR / dividend withholding work,
  step-by-step instructions using Klarwert. No keyword stuffing.
- Pages internally link to each other; home is the pillar page.
- Footer on every page: project name, GitHub link, MIT license, "not
  affiliated with or endorsed by Trade Republic" disclaimer.

## Technical SEO (per page, via shared template)

Head (unique per page):

- `<title>` — keyword-anchored, e.g. `Trade Republic Tax Report from CSV | Klarwert`.
- `<meta name="description">` — unique per page.
- `<link rel="canonical">` — canonical URL for the page.
- Open Graph: `og:title`, `og:description`, `og:url`, `og:type`, `og:image`
  (falls back to a placeholder path until screenshots/og-image are added).
- Twitter card: `twitter:card=summary_large_image` + `twitter:title` +
  `twitter:description` + `twitter:image`.

Structured data (JSON-LD):

- Home: `SoftwareApplication` — name, description, applicationCategory
  (`FinanceApplication`), offers (price 0), operatingSystem, `sameAs` GitHub
  repo, `screenshot` (placeholder until screenshots exist).
- FAQ: `FAQPage` with the questions/answers from the FAQ content.
- Guides: `Article` + `BreadcrumbList` linking back to home.

Crawlability & infrastructure:

- `sitemap.xml` with lastmod; `robots.txt` referencing it.
- Semantic HTML: one `<h1>` per page, logical `h2/h3` hierarchy, descriptive
  `alt` on images.
- `404.html` so GitHub Pages serves a styled not-found page.

Screenshots (optional, later):

- Image slots designed in now (an `assets/` folder, `og-image` placeholder,
  screenshot placeholders on home and relevant guides) so screenshots can be
  dropped in later without changing the build.

## Verification

- `python build_docs.py` then serve `docs/` locally
  (`python -m http.server`) and confirm every page renders.
- Confirm per-page canonicals, Open Graph, JSON-LD, internal links, and the
  404 page work.
- Validate `sitemap.xml` structure and each page's structured data with
  Google's Rich Results Test.
- Confirm `docs/` is committed and GitHub Pages serves it after the one-time
  repo setting.

## Out of scope (this pass)

- Google Search Console submission — not possible on the `github.io`
  subdomain (it belongs to GitHub); requires a custom domain first.
- Screenshots / og-image assets — slots designed in, content added later.
- Off-page promotion (directories, Reddit, Product Hunt) — a separate follow-up.
